# 3.3.16 持久 Root 工作区迁移

## 行为

- 分支 `oo0520-version`；版本 `3.3.16` / `2026111101`，沿用 `io.github.mangi.eta.oo0520` 和原发布签名。
- Root 工作区由 `/data/local/tmp/eta` 改到 `/data/adb/eta/workspace`。chroot 内保持 `/workspace`，新会话的 bind source 改为新目录。交互终端、BusyBox applet、共享挂载根和新后台任务跟随同一常量。
- Android 工具默认的 App 私有 cwd、PRoot rootfs 和用户工作区不变，不把 Root 路径暴露给普通身份。更改只在新 APK 的新会话中生效；旧进程和旧挂载不会被热切换。
- `/data/adb` 不改属主、不放宽模式；工作区浏览、文本预览和导出使用受限 Root 后端。APK/图片分享先二进制复制到 App cache 的独立 UUID 目录，再由 FileProvider 授权只读副本。副本不自动回写原文件；MT 编辑原件仍要求 MT 自身有 Root。
- 原路径的 FileProvider 名称保留，避免破坏已有旧文件 URI；不为新 Root 目录注册一个 App 无法打开的 raw root-path。
- 不自动移动或删除旧目录，也不创建旧路径到新路径的链接。这样不干扰仍持有旧 cwd/日志文件描述符的进程。需要旧项目时，应停掉相关会话后另行备份并迁移；不能把旧目录的丢失解释为本次改动已恢复数据。
- 新 Root daemon 保存显式 `hostWorkspace`；旧 Linux daemon 记录缺少该字段时仍读取旧宿主目录。后台任务的 PID/token 归属检查不变。
- `/data/adb` 和旧、新工作区不能作为用户共享挂载源；恢复的共享挂载配置也重新校验禁区。

## 宿主隔离挂载探测

2026-11-11，Android Root 工具创建 `/data/adb/eta/workspace`，保持 `/data/adb` 和工作区 `0700`。以独立 mount namespace 将其 bind 到现有 Debian rootfs 的 `/workspace`，在 chroot 内确认 cwd、写入、读取和删除临时探测文件均成功。退出后主 namespace 未残留新挂载。该测试只验证路径与当前 Root/SELinux 的兼容性，不等同于新 APK 的端到端测试；新 APK 尚未安装。

## 后端权限探测与复测修正

当前手机的 Root 身份已实际执行新目录的 realpath、stat、find 和含 NUL/0xff 的二进制读取；普通 App UID 10564 实测无法读取该目录。没有放宽 `/data/adb` 的权限。

定向复测发现 LocalFileToolBackend 的读取上限为 16 KiB，而 ShellFileToolBackend 为 512 KiB。复制逻辑现对本地/替身后端使用 16 KiB，Root shell 后端使用 256 KiB；大文件副本仍不受 2 MiB 文本预览限额影响。Windows/MSYS 会改写 `sh -c` 的多层引号，因此 shell 语法测试改用临时脚本文件执行 `sh -n`，保留同样的 payload 检查，不把失败用例跳过。
