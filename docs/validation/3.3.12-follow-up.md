# 3.3.12 收尾修复与发布验收

基线：oo0520-version `e301215d2`（3.3.11 应用功能提交 `78a41a3ab`）。本次仅处理新实测报告及工具调用审查移除，保留既有 Miuix、ColorOS、Root、多会话与虚拟屏架构。

## 分步目标与实现

1. **移除工具调用审查**：删除风险策略与 Shell 风险分析器、智能审查协调器、五档策略、授权队列/缓存、后台通知与 Compose 宿主；删除主设置菜单、搜索词及配方页的审查说明。原生工具直接交回原执行器，不再附加移植功能的风险裁决或人工确认。原有能力开关、Android/Root 权限、工具白名单和判断模型的目录范围保持各自职责。
2. **清理旧配置**：功能配置迁移到 `migration=3`，清除全部 `review_*` 字段，并删除旧授权通知渠道；每次读取及备份导出都会清理旧字段，旧 JSON 备份无法重新启用已删除的审查功能。
3. **修复敏感历史**：配方创建/列表元数据不再标记 sensitive；持久化历史保留工具参数结构、单独省略敏感工具返回，并对常见凭据字段值脱敏。操作作用于深拷贝，当前运行消息和工具结果保持原始数据。上下文摘要使用独立投影，敏感调用只保留工具名和说明，不带入原始入参，也不生成伪 JSON 调用示例。旧 `{"redacted":true}` 被模型复制为新调用时，校验器给出明确 Schema 纠错；Gemini 历史文本与 OpenAI Chat/Responses 历史指令补充占位符说明。
4. **修复辅助模型**：LLM JSON 先丢弃 basic、未知、空白及非字符串组名，再与当前可用组取交集；当合法组非空时把 needs_tools 归一为 true，避免普通“继续”指令触发矛盾异常。置信度越界和非法 JSON 仍明确失败。普通 LLM 升级复判超时至少 6000ms，SystemOne 沿用原超时；保留具体异常摘要并隐藏配置密钥，辅助超时与父运行取消区分。所有辅助模型请求显式清空供应商 systemPrompt，继续关闭可选思考、搜索及自定义 body。
5. **验证与发布**：定向回归、全量失败差集、Lint、原证书签名 APK 与公开 GitHub Release；结果见下方，全部交付步骤已完成。

## 验证范围

- 从实际配方 Schema 创建、列表、下一轮激活并执行，确认管理结果不再错误标记 sensitive。
- 当前运行内原始工具参数/结果与持久化副本隔离，凭据字段省略且配方入参 Schema 不被损坏；旧占位符在 Gemini、OpenAI Chat/Responses 中获得说明与纠错。
- 使用实测的矛盾 JSON、basic/未知组混入和多种非法字段验证解析行为；普通 LLM 原始 HTTP 错误保留原因且不泄露测试密钥；升级主调用 3 秒、复判 6 秒，失败仍保留主判。
- 实际辅助 ProviderRequest 的 systemPrompt 为空、Thinking/搜索/工具关闭、输出上限继续传递；辅助超时不取消父运行。
- 旧 readonly 审查配置迁移后，模拟终端调用可直接到原执行器；旧授权通知渠道清除；主设置只保留渐进加载与 MCP 控件。
- 全量基线沿用既有 48 个失败名称，移除审查功能所对应的通过用例不再纳入分母；不会通过删除失败用例伪造全绿。

没有连接 Android/ColorOS 真机，也没有用户设备数据库或真实模型凭据。报告中的升级模型应在设备上选择已配置凭据的供应商记录（如 CPA · DeepSeek-V4.1-Flash）；代码不会猜测并改写用户模型选择。本次未宣称完成真机或真实 API 联调。
